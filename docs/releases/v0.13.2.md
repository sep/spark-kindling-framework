# v0.13.2 — Runtime and CLI fixes for production deployments

Fixes found while taking a scaffolded domain project to Databricks, plus the CLI pieces that were missing for it: uploading extension wheels, choosing job compute, and a Kindling skill for coding agents. Verified with system tests on Databricks (Unity Catalog), Fabric and Synapse.

Package versions:

- Runtime, CLI, SDK: **0.13.2**.
- Extensions: unchanged (Databricks 0.2.0, Databricks Auto Loader 0.1.0, SDP 0.3.4, Cosmos DB 0.2.0, Temporal 0.2.7, ADX 0.1.0, OpenTelemetry Azure 0.4.0, Visualization 0.1.0).

## Behaviour changes to check

- **Settings lists replace across layers.** A list in a later settings layer used to be appended to the one below. Mappings still deep-merge, but lists and scalars now replace, as config overlays and `kindling bundle build` already did. To append, use Dynaconf's `dynaconf_merge` / `"@merge [...]"` markers.
- **`settings.local.yaml` applies only to the `local` environment.** It used to override every environment run from a checkout.
- **File ingestion `infer_schema` defaults to `False`.** It was documented as `True` but had no effect, so existing entries keep reading string columns.
- **SQL entities must be a single read-only query**, and are read-only whatever their tags say. DDL, DML, session commands and multiple statements are rejected when the entity is declared.
- **Scaffolded packages depend on plain `spark-kindling`.** For existing packages, change `"spark-kindling[standalone]"` to `"spark-kindling"` in `dependencies` and add `pyspark`, `delta-spark`, `pandas` and `pyarrow` to the `dev` group, so lake wheels stop pulling Spark onto clusters.

## Deployed apps run their packages' pipes

On Databricks, Fabric and Synapse, an app's `lake-reqs.txt` packages were installed but only their top-level module was imported. A package in the layout `kindling package init` scaffolds (declarations in `entities/` and `pipes/`, an empty `__init__.py`) registered nothing, so a batch app ran no pipes. Deployed apps now import each package's `entities`, `pipes` and `ingestion` subpackages after the lake wheels and the app's `requirements.txt` are installed, just as a local run does. A new system test covers this on all three platforms.

## Deploying to Databricks

- `kindling runtime deploy --extension NAME` (repeatable) or `--all-extensions` uploads extension wheels to `<artifacts>/packages/`, where cloud bootstrap installs `kindling.extensions` from. Before this, no command put them there.
- `kindling app run --platform databricks` and `kindling runner register` take `--cluster-id`, `--new-cluster`, `--spark-version`, `--node-type` and `--num-workers`. The defaults are unchanged. Serverless job compute is not supported yet. Lakeflow pipelines built with `kindling bundle build` already run on serverless.
- `kindling app run --platform` resolves an app name or path to the deployed folder name, as `app deploy` does, and defaults `--env` to `KINDLING_ENV`.
- The `workspace_<id>.yaml` overlay works when `workspace_id` holds the workspace URL.
- The SDK's `AZURE_BASE_PATH` defaults to empty, matching the CLI.

## Kindling skill for coding agents

`kindling agent setup --agents claude,codex,copilot` installs a `kindling` skill covering entities, pipes, apps, config and getting started on Databricks. It ships inside `spark-kindling-cli`, so it matches the release a project pins, and its examples are executed by the integration tests. `kindling repo init --agents ...` installs it for new repos.

## Other fixes

- SQL entities can be pipe inputs: the built-in `view` provider evaluates the entity's SQL, without needing `migrate apply` to have run.
- File ingestion honours `filetype`, `infer_schema` and every pattern, writes through the destination entity's provider, and fails the run when a parallel table write fails.
- `kindling app run .` and `app run apps/<app>` work.
- Empty fixture stubs in `tests/entities/` no longer hijack local reads. `#` lines in fixture CSVs are comments.
- `--param` for a nested key that older code reads through a flat alias (such as the log level) takes effect.
