# v0.13.0 — The uv conversion

Kindling moves from Poetry to uv end to end: the framework repo's own build, the projects `kindling repo init` / `kindling package init` scaffold, and the devcontainer images. There are no runtime API changes; the minor version marks the toolchain cutover.

Package versions:

- Runtime, CLI, SDK: **0.13.0**.
- Databricks extension: **0.2.0** (unchanged).
- Databricks Auto Loader extension: **0.1.0** (unchanged).
- SDP extension: **0.3.4** (unchanged).
- Cosmos DB extension: **0.2.0** (unchanged).
- Temporal extension: **0.2.7** (unchanged).
- ADX extension: **0.1.0** (unchanged).
- OpenTelemetry Azure extension: **0.4.0** (unchanged).
- Visualization extension: **0.1.0** (unchanged).

## Scaffolded projects are uv projects

`kindling repo init` / `kindling package init` now generate PEP 621 packages built by `uv_build`: the Kindling release wheels are pinned in `[tool.uv.sources]` and dev tooling sits in `[dependency-groups]`. This is the schema `kindling env update` / `env add` / `env bootstrap` already required, so those commands now work on a freshly scaffolded project. The generated CI runs `uv sync && uv run poe test && uv run poe build`, package scaffolds no longer write `src/__init__.py` (uv_build rejects an `__init__.py` above the module root), and the published devcontainer image no longer ships Poetry.

Existing Poetry-schema projects convert with `scripts/migrate_domain_project_to_uv.py` from this repo. A converted project that still has a `src/__init__.py` must delete it, or `uv sync` fails to build the project.

## The framework builds with uv

Every package is a PEP 621 project built by `uv_build`; the repo is a uv workspace (`uv sync`, `uv.lock`) with the CLI and SDK as editable members. `uv.lock` was seeded from the previous Poetry lock, so no resolved dependency version changed. Contributors run `uv sync` once per checkout or worktree; `poe` tasks are unchanged and run through `uv run`.

The published wheels contain byte-identical package files to Poetry-built ones. Their metadata differs in standard ways only:

- `Requires-Python` is `>=3.10`, without Poetry's implicit `<4.0` cap.
- The licence is declared as `License-Expression: MIT` (PEP 639).
- The Cosmos DB extension's extras are published under their normalized names `spark-3-x` / `spark-4-x` (PEP 685); pip still accepts `[spark_3_x]` / `[spark_4_x]`.

## Docs

The setup guide installs from GitHub Release wheel URLs (the packages are not on PyPI yet), and the setup guide and domain quickstart describe the devcontainer image as built. The GitHub Packages guide is removed: GitHub Packages has no Python registry, and the per-platform packages it described never existed.
