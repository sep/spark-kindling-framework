# Release Notes - v0.12.34

This patch adds configurable physical dataset names to Kindling's SDP and
Databricks Lakeflow engines, with validation for generated-name collisions.

## Changes

- Set `kindling.sdp.dataset_naming: leaf` to emit `device_telemetry` for
  logical entity `silver.device_telemetry`. The pipeline destination supplies
  catalog/schema, such as `dev_silver.cwmdp.device_telemetry`.
- Ordinary declarations, internal batch/stream reads, AUTO CDC sources/targets,
  and temporal events/episodes use the configured names consistently.
- Fail before emission on case-insensitive collisions among selected outputs,
  AUTO CDC source views, temporal helper datasets, and implicitly emitted
  chain-episodes siblings. Separate resources can use the same leaf.
- Config values ignore surrounding whitespace and case. Missing/null config
  uses the default; invalid modes are reported with other declaration errors.

## Compatibility and operation

The default remains `normalized`: `silver.device_telemetry` still emits
`silver_device_telemetry`. Logical IDs and pipe function argument keys do not
change. Collision validation is stricter in both modes.

External `EntityNameMapper` behavior is unchanged. Align consumers of leaf
outputs explicitly, for example set entity tag
`provider.table_name: dev_silver.cwmdp.device_telemetry`. This tag is a complete
qualified-name override and takes precedence over catalog/schema tags.

Temporal chain base sources currently use external table resolution even when
a producing pipe is selected locally. Produce these sources in an upstream
resource and configure the matching external name. Generated temporal helper
names remain reserved even when unused by current rules.

## Validation

Focused SDP/Lakeflow, temporal, external-name-resolution, and architecture
unit tests; repository formatting and pre-commit checks. This is a fast-track
release: CI builds and smoke-tests wheels before publication; cloud system
tests are skipped.
