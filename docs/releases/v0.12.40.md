# v0.12.40 — External Delta table resolution in SDP

External Delta batch inputs in SDP and Databricks Lakeflow now resolve their physical table reference through Kindling’s registered `EntityNameMapper`. Entity catalog, schema, explicit table name, and leaf naming metadata are respected independently of the pipeline’s current catalog.

For example, logical entity `bronze.device_telemetry` with catalog `raw_catalog`, schema `iot`, and leaf naming reads `raw_catalog.iot.device_telemetry`, even when the pipeline catalog is `pipeline_catalog`.

Internal pipeline references retain emitted dataset names for graph inference. Pipe APIs retain logical entity IDs, and provider-owned streaming sources retain their existing read path. No application pipeline changes are required.

Package versions:

- Runtime, CLI, SDK: **0.12.40**.
- SDP extension: **0.3.3** (contains this fix; upgrade this extension).
- Databricks extension: **0.1.10** (unchanged; inherits the fix with SDP **0.3.3**).

Validation: focused SDP, temporal lowering, and Databricks engine tests passed **187 tests, 1 skipped**. Formatting and whitespace checks passed. This fast-track release builds wheels and runs artifact smoke tests; full CI and cloud system tests are skipped. Live Lakeflow validation was not performed.
