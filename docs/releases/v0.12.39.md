# v0.12.39 — Declarable Event Hub sources for Lakeflow

Normal Kindling ingestion pipes with Event Hub driving inputs can now declare Databricks Lakeflow streaming tables and append flows. Event Hub uses Kafka transport; Lakeflow owns checkpoints and execution. SDP lowering honors `driving_entity_ids`, including non-default input positions.

Package versions:

- Runtime, CLI, SDK: **0.12.39**.
- SDP extension: **0.3.2**, requiring runtime **0.12.39+**.
- Databricks extension: **0.1.10**, requiring runtime **0.12.39+** and SDP **0.3.2+**.

The provider capability validates source configuration without reading Spark data or exposing secret values. The declarative Event Hub path retains Kafka fields alongside Kindling aliases; existing batch behavior is preserved. OSS SDP explicitly rejects unsupported provider streams.

See [the entity guide](../guide/data_entities.md) for the entity and pipe configuration pattern.

Validation: the rebased implementation passed 2,913 unit tests (2 skipped); Copilot corrections passed 94 targeted tests, formatting, and commit hooks. PR #283 passed CI unit, quality, packaging, security, and wheel-build checks before merge. This is a fast-track release: release wheel builds and smoke tests remain enabled; cloud system tests are skipped.

Live Lakeflow validation has not yet been performed. Streaming-table target schemas are inferred from flow output; entity schemas are not forwarded as explicit target schemas. Remaining scoped pylint findings and parallel-only bootstrap test-order sensitivity are documented follow-ups.
