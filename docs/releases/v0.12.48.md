# v0.12.48 — Cosmos DB: change-feed streaming, throughput controls, Spark 3/4 connector matrix

A single-feature release: the Cosmos DB entity provider extension grows from a batch-and-sink provider into a full streaming source with run-level throughput configuration, a formal merge, and a connector coordinate for every Spark line Kindling runs on. The runtime, CLI and SDK carry no code changes and are bumped for the release.

Package versions:

- Runtime, CLI, SDK: **0.12.48**.
- Cosmos DB extension: **0.2.0** (from 0.1.0).
- Databricks extension: **0.1.14** (unchanged since 0.12.44).
- SDP extension: **0.3.4** (unchanged since 0.12.44).
- Temporal extension: **0.2.7** (unchanged since 0.12.43).

## Change-feed streaming reads

`CosmosEntityProvider` now implements `StreamableEntityProvider` and `DeclarableStreamingSource`. `read_entity_as_stream()` reads the container's change feed through the connector's `cosmos.oltp.changeFeed` data source, so a Cosmos entity can be the driving input of a streaming pipe alongside Delta, Parquet and Event Hubs. Nothing in `pipe_streaming` changed: the streaming starter gates on the interface. Continuation tokens are Spark Structured Streaming's responsibility and live in the sink's checkpoint.

Three tags configure the source. `provider.changefeed.mode` is `latest_version` (default; connector `LatestVersion`, deletes not visible) or `full_fidelity` (connector `AllVersionsAndDeletes`; the container must be provisioned for it). `provider.changefeed.start_from` is `Beginning` (default), `Now`, or a UTC instant in the connector's `ISO_INSTANT` form such as `2026-01-31T00:00:00Z`; keywords are accepted case-insensitively and emitted in the connector's spelling, and date-only, zone-naive or non-UTC-offset values are rejected at validation time rather than at stream start. `provider.changefeed.items_per_trigger` is an optional positive micro-batch size hint.

`streaming_source_spec()` returns an inert, secret-safe declaration for SDP/Lakeflow lowering: option names and the `database/container` identity only, never credentials or endpoint values. Only a *driving* Cosmos input lowers; a non-driving Cosmos lookup is not declarable in an SDP pipe because the declaration engine reads only Delta externals in batch, the same limitation every non-Delta provider has there.

## Config-first throughput controls (`kindling.cosmos.*`)

A whole-container read with the connector's default partitioning can draw a large share of a container's RU/s. The connector's knobs are now run-level configuration applied to every Cosmos read and write below per-entity `provider.option.*` overrides ("config dictates, tags override"). `kindling.cosmos.read.partitioning_strategy` (default `Default`) and `kindling.cosmos.read.max_item_count` (default `1000`) are always emitted explicitly. `kindling.cosmos.throughput_control.enabled` (default `false`) turns on the connector's Throughput Control; when enabled, `group_name` and exactly one of `target_threshold` (fraction in `(0, 1]`) or `target_throughput` (absolute RU/s) are required, because the connector asserts the group name and rejects both targets together. `global_control.database` and `.container` are optional as a pair; without them Kindling emits `globalControl.useDedicatedContainer=false` so the connector splits the budget across executors instead of requiring a control container. Invalid combinations fail in Kindling with the configuration key named, not in the JVM at query start.

## Formal merge honouring `write.mode`

Cosmos writes were already idempotent upserts by `(id, partition key)`. `merge_to_entity()` declares that formally, so the persist path treats a Cosmos entity with `merge_columns` as merge-capable instead of falling back to append. The DataFrame must carry an exact `id` column. The entity's `write.mode` tag selects the strategy on every write path (`write_to_entity`, `append_to_entity`, `merge_to_entity`, `append_as_stream`), the way it does for Delta and memory entities: `insert` writes with `ItemAppend` (insert if absent, existing documents untouched), `merge` writes with `ItemOverwrite`; an explicit `provider.write_strategy` must agree, and `ItemDelete` is never a merge. Honouring the tag on `write_to_entity` matters because the persist path calls it when the destination is not known to exist (`provider.assume_exists: false`). A `provider.option.spark.cosmos.write.strategy` passthrough that conflicts with a mode- or merge-selected strategy is rejected rather than allowed to turn a merge into a delete; ordinary writes without `write.mode` keep the documented passthrough precedence.

Named read and write tags (`infer_schema`, `query`, `write_strategy`) are now laid down before the `provider.option.*` passthrough in every option builder, so the documented rule that the passthrough always wins holds for those too.

## Connector coordinate per Spark line

The Cosmos Spark connector is a JVM artifact built per Spark minor and Scala binary; the Python wheel cannot install it. The extension now publishes `COSMOS_SPARK_CONNECTOR_MAVEN_COORDINATES`, a table keyed by Spark line at connector 4.49.2: 3.4 and 3.5 on Scala 2.12 (Fabric, Synapse, Databricks 13–16), 4.0 and 4.1 on Scala 2.13 (Databricks 17+, Spark 4 standalone). `resolve_cosmos_spark_connector_coordinate()` returns the row for the installed `pyspark` or a given version string; no Spark session is consulted. `COSMOS_SPARK_CONNECTOR_MAVEN_COORDINATE` still names the Spark 3.5 artifact for existing consumers.

The wheel gains `spark_3_x` and `spark_4_x` extras that pin `pyspark` to a Spark family for local and CI environments, named by Spark line rather than platform. Managed runtimes install the bare wheel as before; the provider code is Spark-version neutral and only names the data source format and options. The provider takes an optional `ConfigService`; direct construction with only a logger provider still works.

## Cosmos extension system test runs locally again

`tests/conftest.py` enables Kindling's Delta session config, so the provider's session applied the Delta catalog while only the Cosmos connector jar was on the classpath, and every action failed with `Cannot find catalog plugin class ... DeltaCatalog`. The fixture now builds the session through `configure_spark_with_delta_pip` with the connector as an extra package, resolving the coordinate for the installed pyspark's Spark line. A live change-feed streaming round trip joins the existing upsert round trip. Both pass against the dev account on PySpark 3.5 with the Spark 3.5 artifact and, in a Spark 4.0.4 / Scala 2.13 probe, with the Spark 4.0 artifact.
