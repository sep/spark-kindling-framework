# Release Notes - v0.12.1

A focused patch on CLI credential pre-flight, driven by a workspace whose
Databricks personal access tokens are disabled by policy.

## Pre-flight now accepts the SDK's real auth alternatives

`kindling app run --platform databricks` and `kindling env check` used to
hard-require `DATABRICKS_TOKEN`, even though the SDK itself supports two
other paths: a service principal (`AZURE_TENANT_ID`/`AZURE_CLIENT_ID`/
`AZURE_CLIENT_SECRET`) or a plain `az login` session. Workspaces with PATs
disabled by policy — increasingly common under Unity Catalog governance —
were blocked at pre-flight despite being fully usable.

Pre-flight now evaluates all three alternatives, in the SDK's own
resolution order, and only fails if none are satisfied:

```
export DATABRICKS_HOST=https://your-workspace.azuredatabricks.net
az login
kindling env check --platform databricks   # passes via az-cli session
```

If none are configured, the failure message lists all three options,
including the PAT-disabled workaround (minting an Entra ID token for the
Databricks first-party resource directly).

## Fabric and Synapse pre-flight tables reconciled

The same audit surfaced two related gaps, now closed:

- `env check --platform fabric` now checks `FABRIC_LAKEHOUSE_ID` alongside
  `FABRIC_WORKSPACE_ID`, matching what `FabricAPI.from_env` actually
  requires.
- The Synapse run gate now requires `SYNAPSE_SPARK_POOL_NAME` alongside
  `SYNAPSE_WORKSPACE_NAME` — previously a run without a pool name passed
  pre-flight and then failed downstream against `sparkPools/None`, a
  confusing failure far from its cause.
- `env check --platform fabric|synapse` now treats a **wholly absent**
  service principal triple as fine (an informational note that `az login`
  or a managed identity will be used), while a **partial** triple still
  fails, naming the missing variables — the SDK silently ignores a
  partial triple and falls through, so pre-flight is where users should
  learn about it.

**Note for CI:** jobs that relied on `env check --platform fabric|synapse`
failing when no service principal is configured will now pass in that
case. If your pipeline specifically wants to enforce SP presence, check
for the SP variables directly rather than relying on this command.

## Upgrade

```bash
kindling env update --version 0.12.1
```
