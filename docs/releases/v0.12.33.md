# Release Notes - v0.12.33

This patch adds multiple driving inputs to batch pipes, streaming pipes,
and temporal chains.

## Changes

- Declare `driving_entity_ids` to read multiple batch inputs incrementally.
  Each source has its own watermark cursor, and the pipe runs whenever any
  driving input has data. Other inputs remain full reference reads.
- Streaming pipes read every declared driving input as a stream and
  references as static inputs. The pipe body receives each input separately
  and performs any union.
- Temporal chains accept base events from multiple source entities,
  preserve first-registration source order, and union per-source event
  envelopes. The previous engine/config opt-in is no longer required.
- A failed cursor save after successful output persistence retains that
  source's capture for retry while allowing other source cursors to save.
  Retry reads no longer produce misleading missing-lifecycle warnings.

## Compatibility and operation

Omitting `driving_entity_ids` retains the first-input default. Output
persistence precedes cursor saves; cursor updates are independent, so
outputs must tolerate replay if a cursor save fails.

Streaming pipes still use one query and checkpoint per pipe. Changing an
existing query's streaming source list requires a new checkpoint and a
plan for replay. This release does not change SDP's generic pipe lowering
to honor arbitrary driving-input declarations; that remains follow-up work.

Collector registration sugar and keyed multi-writer fan-in remain proposed.
