# v0.14.1 — Provenance stamping, runtime manifest

A feature release on the 0.14 line. Output rows can now record which pipe,
run and inputs wrote them, and every initialization records what it ran on.
Both are off or passive by default, so upgrading from 0.14.0 changes no
table and no result.

Before 1.0, Kindling shifts semver one place right: a `0.MINOR` release may
break things and a `0.x.PATCH` release brings features and fixes. That is why
these features ship as 0.14.1.

Package versions:

- Runtime, CLI, SDK: **0.14.1**.
- SDP and Databricks extensions: **0.14.1** (both require
  `spark-kindling>=0.14.1,<0.15`; Databricks also requires SDP 0.14.1).
- Other extensions: unchanged at **0.14.0** (Cosmos DB, Temporal,
  OpenTelemetry Azure, ADX, Databricks Auto Loader, Visualization). They work
  with 0.14.1.

## Provenance stamping

An output entity can carry a nullable `__provenance` struct column that names
the pipe, run and inputs that wrote each row. It is data, not telemetry: it
lives in the row, you query it with SQL, and turning tracing off doesn't
turn it off.

Turn it on for a whole project in any settings layer:

```yaml
kindling:
  provenance:
    enabled: true
    pipe_tags: [domain, owner, "layer.*"]   # pipe tags copied into the stamp
```

Or per entity, with `provenance.enabled`, `provenance.column` and
`provenance.pipe_tags` tags. An entity opts out of the project default with
`provenance.enabled: "false"`. The settings default reaches Delta and memory
entities only; it skips read-only, SQL, SCD2 companion and `system.*`
entities.

- **What a stamp holds:** `pipe_id`, `pipe_name`, `run_id`, `execution_id`,
  `persist_id`, `processed_at`, `mode` (`batch`, `streaming` or `sdp`), app,
  environment, platform and Kindling version, `input_entity_ids`, the
  allow-listed pipe `tags` and `schema_version`. `input_versions` is reserved
  and null for now. Pipe tags that held a resolved secret are never copied.
- **Every write stamps, and a stamp is never a change.** Appends, merges and
  SCD2 versions carry the stamp of the write that stored them. A
  provenance-only difference opens no SCD2 version and triggers no in-place
  update. So enabling stamping on an existing SCD2 table re-versions nothing;
  existing rows keep a null stamp until they are next written. An SCD2 close
  keeps the closed version's stamp.
- **Batch, streaming and SDP.** The batch persist step (after surrogate
  keys), the start of a streaming pipe and the SDP dataset builder all stamp.
  On Lakeflow, the column is in AUTO CDC's `track_history_except_column_list`
  unless the entity has an `scd.tracked` allow-list.
- **Downstream reads drop an input's stamp**, so a table never inherits a
  stamp naming another pipe. A pipe keeps it for named inputs with the
  `provenance.keep_inputs` pipe tag.

See "Provenance Stamping" in `docs/guide/data_entities.md`.

## Runtime manifest

Each `initialize_framework` builds a runtime manifest,
`kindling.runtime_manifest.get_runtime_manifest()`, recording:

- a `run_id` for the initialization, and the executor run ids made under it;
- the platform, runtime, Spark, PySpark, Delta and Python versions;
- the Kindling version requested (e.g. `latest`) and the one resolved;
- the loaded extensions and the app;
- the key runtime packages, plus every package an install added or replaced
  and what caused it;
- a runtime fingerprint and a package fingerprint.

The bootstrap logs the manifest on one INFO line and emits a
`runtime_manifest` span before an auto-run app starts. Batch and streaming
provenance stamps carry its `run_id`.

App dependency installs now report every package they add or replace.
Pinning the runtime's key packages during an app install, as extension
installs do, is opt-in with `kindling.apps.pin_runtime_packages: true`.

## Upgrading from 0.14.0

1. **Nothing to do unless you turn provenance on.** It is off by default.
2. **Upgrading the SDP or Databricks extension needs Kindling 0.14.1.**
   Move them together, e.g. with `kindling env update`.
3. **A `__provenance` column of your own conflicts with stamping.** Once
   stamping is enabled for an entity, registration rejects the column in its
   declared schema, and a write fails if the pipe's output already has it.
   Rename the stamp with `provenance.column`.
4. **New streaming signals.** `StreamingOrchestrator` emits
   `streaming.pipe_starting` and `streaming.pipe_start_failed` around each
   pipe's start.

## Fixes

- **`streaming.orchestrator_stopped` names the run it stopped.** It carried
  `run_id=None` and `stopped_query_count=0` because the payload was read after
  the run state was reset.

## For contributors

- `poe version --bump_type patch_rc` cuts a patch release candidate
  (0.14.0 -> 0.14.1rc1; rcN -> rc(N+1)).
- The single-process test run no longer runs out of memory. Tests now release
  JVM state that outlived them: Delta's static `DeltaLog` cache, stopped
  sessions held by AQE and broadcast pool threads, and each test's temp views.
