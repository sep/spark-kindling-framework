# v0.12.45 — Test suite green under `--suite all`

A test-only release. No package code changes; the runtime, CLI and SDK wheels are rebuilt at the new version so the release line stays contiguous, and this is the first fully validated release since 0.12.42 — the intervening releases were fast-tracked, so this one runs the complete unit, integration, quality, security and cloud system lanes.

Package versions:

- Runtime, CLI, SDK: **0.12.45**.
- Databricks extension: **0.1.14** (unchanged since 0.12.44).
- SDP extension: **0.3.4** (unchanged since 0.12.44).
- Temporal extension: **0.2.7** (unchanged since 0.12.43).

## What was wrong

Running the repository's own definition of "all tests" — `--suite all --path tests` — in one process failed 18 unit tests and one collection error on top of the one integration test that had been red on `main` since at least 2026-09-10. Every one of those tests passes in isolation. None of them was a product defect; all were state leaking between tests in the same process, which the per-suite CI jobs never exercise in combination. Three root causes.

**Ambient injector state.** `test_sdp_mode`'s real-Spark dataset test built `OssSdpEngine` without an `external_read_resolver`, so its default reader called `GlobalInjector.get(EntityNameMapper)` and got whatever binding the worker happened to hold — `ConfigDrivenEntityNameMapper` is autobound on *import* of `kindling.entity_resolution`, and several tests reset the injector. That is why CI showed a different error on each run for the same cause. The test now binds the real mapper explicitly, as every other integration test touching it already did, and serves the same fake config to the mapper's namespace lookup so the production `_read_external_entity` path completes rather than an assertion being silently swallowed inside a `try/except`.

**A module reload splitting class identity.** `tests/integration/test_config_integration.py` called `importlib.reload(kindling.spark_config)` in four tests to re-register `DynaconfConfig` after `GlobalInjector.reset()`. A reload mints brand-new `ConfigService`/`DynaconfConfig` class objects for the rest of the process, while `kindling.bootstrap` keeps the originals it imported at module level — so seventeen later unit tests across six files failed with `KeyError` on fake-injector dicts that visibly contained `ConfigService`. Three other tests in the repository already carried comments warning against exactly this reload; the file now uses their sanctioned alternative, `GlobalInjector.singleton_autobind()(DynaconfConfig)`.

**A process-global environment variable.** `register_kindling_loaders()` — reached by that same file's real `configure_injector_with_config` path — writes the Dynaconf loader chain into `os.environ["LOADERS_FOR_DYNACONF"]` and nothing restored it. Every `Dynaconf(...)` constructed afterwards ran Kindling's `@secret` loader at load time, so the overlay suite's structural-control test — which asserts a `@secret:` literal *survives* without a re-overlay — saw the reference already resolved before its code under test ran. An autouse fixture in `tests/conftest.py` now snapshots and restores the variable around every test, guarding the whole class of leak rather than the one instance.

Separately, `tests/local/test_dependency_compatibility.py` is a standalone script (`python tests/local/… --platform fabric`) whose function is named `test_*`; pytest collected it and errored on a `platform` fixture that exists nowhere. It joins `tests/local-project` in `norecursedirs`.

## Upgrading

Nothing to do. No runtime behavior changes; the extension wheels are unchanged and need not be re-pinned.

One thing worth knowing for local development: system tests are **not** auto-skipped without cloud credentials — only `--skip-system` or `--require-platform-env` gate them — so a bare `poe test` on a developer machine fails 27 cloud tests as environment noise rather than breakage. Making `poe test` pass `--skip-system` by default is a sensible follow-up.

Validation: `--suite all --skip-system` on the released tree, one process: **3136 passed, 94 skipped, 0 failed, 0 errors** — up from 3120 passed / 18 failed / 1 error before the fixes. Both cross-suite reproducers (the integration file first, then the affected unit files) pass 62/62 and 93/93. This is a full release: every CI lane runs before the wheels publish.
