# v0.13.3 — Job parameters override settings lists

A patch release for one configuration bug found while verifying the 0.14.0 work on Databricks.

Package versions:

- Runtime, CLI, SDK: **0.13.3**.
- Extensions: unchanged (Databricks 0.2.0, Databricks Auto Loader 0.1.0, SDP 0.3.4, Cosmos DB 0.2.0, Temporal 0.2.7, ADX 0.1.0, OpenTelemetry Azure 0.4.0, Visualization 0.1.0).

## A job parameter list now replaces the settings files' list

A list setting passed as a job parameter or with `--param` could not override the same list in an app's `settings.yaml`.

- **Why.** Parameters were applied through Dynaconf's merge, which appends lists.
- **Effect.** For example, passing `kindling.extensions` as a job parameter left the app's own extension pins in place, and the bootstrap kept the file's version.

Parameter lists now replace the settings files' lists, the same rule that applies between settings files. A list can still opt into appending with Dynaconf's `dynaconf_merge` marker, as in the files.

This works for every form of the parameter (`kindling.extensions`, a nested `kindling` mapping, or the legacy flat `extensions` key) and on every supported Dynaconf version. That matters because clusters install Dynaconf 3.3.1, where even Dynaconf's non-merging update appends lists.

**Who is affected:** jobs that set a list (`kindling.extensions`, `kindling.required_packages` or any other) through job parameters or `--param` while a settings file sets the same key. Scalars and mappings were not affected.
