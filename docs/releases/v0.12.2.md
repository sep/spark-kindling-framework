# Release Notes - v0.12.2

Comprehensive built-in tracing instrumentation, plus a fix for a Databricks
ad-hoc run crash introduced by the SDK version bump in 0.12.0.

## Comprehensive tracing instrumentation (gh#210)

Every major framework operation now produces a coherent span tree, on all
three trace providers (event-based, plain-Python JVM-free, and Azure
Monitor/OTel):

- **Entity-provider operations** (read/write/append/merge/replace/ensure/
  stream setup) are traced automatically at the `EntityProviderRegistry`
  chokepoint — no per-provider code changes, `isinstance`/`hasattr`
  transparency preserved, micro-batch hot loops never produce spans.
- **Structural seams**: pipe read/persist, watermark cursor management,
  config reload, migration plan/apply, DAG orchestrator plan/generation/
  pipe (covering retries), streaming orchestrator lifecycle and recovery,
  file ingestion, job deploy/create/run.
- **Bootstrap span tree**: phase windows from config download through app
  run are recorded and retro-flushed once a trace provider is available,
  via a new `SparkTraceProvider.record_span` (a concrete default, so
  existing third-party providers keep working unmodified).
- **Design-time CLI spans**, gated by `KINDLING_TRACE=1`.
- **New config**: `kindling.telemetry.tracing.enabled` (default `true`) and
  `kindling.telemetry.tracing.level` (`minimal`/`standard`/`verbose`,
  default `standard`).
- Spans now carry an explicit `parent_id`, so trees are linked rather than
  inferred from time containment — consecutive top-level operations in one
  session also get distinct trace ids instead of blurring together.
- Public `kindling.test_framework.RecordingTraceProvider` for asserting
  span structure in your own tests.

**Breaking for dashboards**: span component/operation names are normalized
to a `kindling.<area>` convention (e.g. `data_pipes_executer/
execute_datapipes` → `kindling.pipes/run`). Dashboards or alerts keyed on
the old names need to re-key. Span attributes are now whitelisted per
seam — tags and caller-supplied details are no longer exported wholesale,
since they may carry credential references.

**Also fixed along the way**: a data-correctness bug where a failed
merge/append could silently advance the watermark past unpersisted data
(the persist span was swallowing the failure); a `TypeError` on the first
manual span under the Azure Monitor provider; a mislabeled trace component
in file ingestion.

See `docs/proposals/obsolete/comprehensive_tracing_instrumentation.md` for the full
design record.

## Fixed

- **Databricks ad-hoc app runs no longer crash with `AttributeError`**
  (gh#214). `kindling app run --platform databricks` called
  `self.client.jobs.runs.submit(...)`, but `WorkspaceClient.jobs` has no
  `.runs` sub-namespace on the SDK version this project now requires (the
  `databricks-sdk` floor raised in 0.12.0) — `submit` is a direct method
  on `jobs`, matching every other call site in the file. This affected
  every ad-hoc Databricks run on 0.12.0 and 0.12.1.

## Upgrade

```bash
kindling env update --version 0.12.2
```

If you run Databricks apps, this release is important regardless of
whether you use tracing — upgrade to unblock `app run`.
