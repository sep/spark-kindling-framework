# Release Notes - v0.12.4

Three related temporal-extension improvements: `MemoryEntityProvider` gains
real SCD2 merge support, condition rules can now be declared directly in
code instead of only as data, and `ingest_conditions()` fails clearly
instead of crashing against a provider that can't merge.

## MemoryEntityProvider gains merge_to_entity (SCD2) support (gh#220)

The in-memory provider now supports the same `merge_to_entity` contract as
`DeltaEntityProvider` — SCD Type 2 upsert (`scd.type=2`), insert-only
(`write.mode=insert`), and full-row SCD1 upsert (default) — implemented as
plain DataFrame joins/unions rather than a Delta `MERGE INTO`. This lets
`kindling_ext_temporal.ingest_conditions()` (and any other caller that
merges into an entity) be exercised against Memory, the framework's
no-external-dependency test provider, instead of requiring a real Delta
table.

Along the way: `augment_schema_for_scd2`, `quote_sql_identifier`, and
`build_null_safe_change_condition` moved from `entity_provider_delta.py`
(private, Delta-only helpers) to `data_entities.py` as public,
provider-agnostic functions — `DeltaEntityProvider` behavior is unchanged.

## Registry-declared temporal conditions (gh#222)

Condition rules previously had exactly one representation: rows in the
`silver.conditions` table, ingested through `ingest_conditions()`. That's
still the right model for high-cardinality, frequently-changing rules, but
the wrong shape for a small set of static, application-owned rules that
would rather be native PySpark expressions than serialized SQL strings.

A second, explicit `condition_source` is now available per condition
engine:

```python
from pyspark.sql import Column, DataFrame
from pyspark.sql import functions as F
from kindling_ext_temporal import DataConditions, DataEvents

def overheat_enter(events: DataFrame) -> Column:
    return events["payload"].getItem("temperature").cast("double") > F.lit(90)

def overheat_exit(events: DataFrame) -> Column:
    return events["payload"].getItem("temperature").cast("double") <= F.lit(90)

DataConditions.register(
    condition_id="condition.system_overheat",
    consumes_event_type=["telemetry.observed"],
    subject_type="machine",
    enter_when=overheat_enter,
    exit_when=overheat_exit,
)

DataEvents.condition_engine(engineid="static_conditions", condition_source="registry")
```

- `enter_when`/`exit_when` are `Callable[[DataFrame], Column]` predicate
  builders, invoked with the scoped events DataFrame at execution time —
  not bound `Column` objects, so a declaration never captures a Spark
  session or execution plan.
- Registry declarations are code: required fields and duplicate
  `condition_id`s raise immediately (fail fast), rather than being
  quarantined like table rows.
- `condition_source="table"` (the default, unchanged) keeps reading from
  the configured current conditions entity exactly as before.
- Both sources normalize to the same internal representation and emit the
  same `{condition_id}.entered`/`.exited` boundary events — a table rule
  and a registry rule can execute side by side in the same pass.
- Chain lowering (`declare_temporal_chain`/`collapse_temporal_chain`) omits
  the conditions-current input entirely for engines that are entirely
  registry-sourced.
- Design doc: `docs/proposals/obsolete/temporal_condition_sources.md`.

## Fixed

- **`ingest_conditions()` no longer crashes with a raw `AttributeError`
  against a non-merge-capable provider** (gh#221): it now raises a clear
  `ValueError` naming the entity and provider type when the resolved
  provider doesn't implement `merge_to_entity` (csv, parquet, sql, adx
  today), matching the existing guard pattern in
  `simple_read_persist_strategy.py`.

## Upgrade

```bash
kindling env update --version 0.12.4
```

`spark-kindling-ext-temporal` is versioned independently (now `0.2.6`) and
is not covered by `kindling env update` — see the extension's own
installation path if you consume it directly.
