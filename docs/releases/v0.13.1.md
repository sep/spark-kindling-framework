# v0.13.1 — Scaffolding fixes for the uv conversion

Fixes to `kindling repo init` / `package init` / `package add` found while bringing up repos scaffolded by 0.13.0, plus documentation corrected against the code. No runtime API changes.

Package versions:

- Runtime, CLI, SDK: **0.13.1**.
- Extensions: unchanged (Databricks 0.2.0, Databricks Auto Loader 0.1.0, SDP 0.3.4, Cosmos DB 0.2.0, Temporal 0.2.7, ADX 0.1.0, OpenTelemetry Azure 0.4.0, Visualization 0.1.0).

## Scaffolded repos bootstrap in their devcontainer

`kindling repo init` now writes a root `pyproject.toml`: a non-package uv workspace (`<repo>-workspace`) over `packages/*`. On 0.13.0 the generated devcontainer's `kindling env bootstrap` failed at the repo root with "No pyproject.toml found". It now pins Kindling in the root (adopting the release a package already pins, or the latest release for an empty repo) and syncs one repo-wide `.venv/`, which the devcontainer uses as its interpreter. An existing root `pyproject.toml` is kept, and `repo init` prints the workspace table to add to it.

`kindling package init` refuses a package name equal to the root project's name and pins the release the root already pins, so every workspace member agrees.

**Repos scaffolded with 0.13.0 or earlier** add the root file by hand (the domain project quickstart shows it), then run `kindling env bootstrap` at the repo root. Projects converted with `scripts/migrate_domain_project_to_uv.py` that still contain a `src/__init__.py` must delete it.

## `package add` output is registered

`kindling package add entity` / `pipe` / `ingestion` wrote modules the runtime never imported: a flat `entities.py` shadowed by the scaffolded `entities/` package, and pipes in namespace directories outside the `entities`, `pipes` and `ingestion` namespaces Kindling walks. They now write `entities/<ns>.py` and `pipes/<ns>_<name>.py`, declare a pipe's output entity when it is missing, name test stubs `test_<ns>_<name>.py`, and put tests and CSV fixtures under the package's project root. `--package` accepts either `packages/<pkg>` or `packages/<pkg>/src/<pkg>`.

## Working in a package

Inside a package directory use `uv run poe test` / `uv run poe build`: in the workspace, a bare `uv sync` there is an exact sync of that one package and removes the others from the shared `.venv/`. Resync the whole repo with `uv sync --all-packages` at the root. The generated CI follows the same rule.

## Devcontainer image

The published image now includes the checksum-verified `kindling-abfss-local-auth.jar` and gives the `vscode` user ownership of `/opt/hadoop-jars`, so `kindling env ensure --cloud azure` can add or refresh JARs in the container.

## Docs

The build system doc, CLI reference (whose `env` commands still described Poetry), setup and quickstart guides, READMEs and dev stories were corrected against the current code.
