# Release Notes - v0.12.3

The temporal extension's chain lowering is now self-maintaining: the broken,
per-declaration pipe graph it replaces gets collapsed out automatically,
instead of sitting alongside it forever.

## Temporal: automatic chain collapsing (gh#206)

`declare_temporal_chain()` only ever *added* the two composite chain pipes;
it never removed the per-declaration base-event/condition-engine/episode/
episode-event pipes those chain pipes supersede. A naive "run everything
registered" then executed both lowerings over the same declarations — the
per-declaration lowering is the broken, cyclic, multi-writer shape the chain
exists to replace, so that combination was never actually wanted.

- **New `collapse_temporal_chain()`**: does everything `declare_temporal_chain`
  does, then also unregisters the superseded per-declaration pipes, returning
  the corrected pipe id list.
- **New `kindling.temporal.autocollapse` config key** (default `true`): any
  `run_datapipes`/`run_datapipes_dag` call whose requested pipes reference a
  per-declaration temporal pipe is automatically collapsed before execution
  starts — including DAG-mode runs. Most apps never need to call
  `collapse_temporal_chain()` directly. Disable with
  `kindling.temporal.autocollapse: false` to run one granular per-declaration
  pipe standalone (e.g. for debugging).
- Every temporal pipe now carries a `temporal.lowering` tag (`declared` for
  per-declaration pipes, `chain` for the composite chain pipes), exported as
  `TEMPORAL_LOWERING_TAG`/`TEMPORAL_LOWERING_DECLARED`/`TEMPORAL_LOWERING_CHAIN`
  — the reliable way to distinguish the two lowerings, since `pipeid` itself
  is user-overridable.
- **New `DataPipesRegistry.unregister_pipe()`** primitive — the registry
  previously had no removal method at all.

`declare_temporal_chain()` is unchanged and still available for when you
deliberately want both lowerings registered side by side (e.g. inspecting one
hop in isolation with autocollapse disabled).

**Known gap**: the Databricks SDP/Lakeflow engine path doesn't call
`run_datapipes`, so autocollapse doesn't reach it — apps on that engine still
call `collapse_temporal_chain()`/`declare_temporal_chain()` explicitly before
SDP declares its dataset graph.

## Upgrade

```bash
kindling env update --version 0.12.3
```
