# v0.12.42 — Temporal chain episodes for non-default chain ids

Databricks Lakeflow temporal chains registered under a chain id other than `default` silently declared no episode branch. `collapse_temporal_chain("<id>")` records `temporal.chain_id` on the two composite chain **pipes**, but `DatabricksSdpEngine` read it from the output **entity**'s tags, which never carry it. The sibling lookup therefore asked for `temporal.chain.episodes.default`, found nothing, and passed `episodes_name=None` into the lowering — which skips its whole episode block.

Package versions:

- Runtime, CLI, SDK: **0.12.42**.
- Databricks extension: **0.1.12**, requiring runtime **0.12.39+** and SDP **0.3.2+**.
- SDP extension: **0.3.3** (unchanged since 0.12.40).

The failure was silent by construction. The pipeline update succeeded, `<events>__g0..gK` and `<events>` were declared normally, and only `episodes`, `episodes__episode_snapshot` and `<events>__determinations` were missing. `episodes_name=None` is a legitimate configuration for a chain with no episode definitions, so there was nothing for the engine to warn about. The identical mistake was present in `_emitted_dataset_names`, the reservation path behind `validate()`, so name reservation agreed with emission and stayed self-consistently wrong. Both call sites now read the chain pipe's own tags; entity tags remain where they belong, feeding `scd_spec_from_tags`. The defect was independent of `temporal_mode` and affected every chain whose id was not `default`.

Also in this release: `kindling.lakeflow.temporal_strata_materialization` (`table` default, `view` opt-in) chooses whether the numbered event strata `<events>__g0..gK` are persisted. `view` declares them as pipeline-scoped temporary views, so no `__g*` tables are created and nothing intermediate is written. Only the numbered strata change — the determinations view, higher-order boundaries, the episodes Auto CDC target and the public events union are declared identically, so results are unchanged. It requires `kindling.lakeflow.temporal_mode: batch` and fails the declaration otherwise, because a streaming stratum is an append-flow target that a temporary view cannot be.

Weigh that option carefully. Generation `k` reads every stratum below it, so a temporary view is re-expanded once per reference instead of read back from storage: the plan behind `events` grows exponentially in `kindling.temporal.max_generations`, on the order of `2^K` rescans of the base stratum at ceiling `K`. It is sound at a ceiling of 1–3 and a poor trade at the default of 10. It also removes per-generation observability — no `__g*` table to query when determining which generation produced an event, and no per-stratum metrics in the event log. Prefer `table` unless storage or write amplification is the binding constraint. The canonical `spark.kindling.lakeflow.temporal_strata_materialization` bundle key is point-looked-up by the Lakeflow selector, so it also resolves on restricted runtimes.

Upgrading: this is a declaration-time defect inside the Databricks extension, so an affected pipeline needs the **0.1.12** extension wheel deployed before the episode branch appears. A normal triggered update then suffices — batch strata are stateless recompute and the episodes target is created fresh. No dataset cleanup is required: nothing incorrect was materialized, and the previously declared strata and events surface remain valid.

Validation: 2,952 unit tests passed (2 skipped); pylint unchanged at 8.61. The regression test builds a chain under a custom id and asserts the full episode branch, failing on the unfixed code; the pre-existing lowering tests only ever built the `default` chain, which is why this was not caught earlier. Four further tests cover the new option: view lowering, the `table` default, rejection in streaming mode, and rejection of an unknown value. This is a fast-track release: release wheel builds and smoke tests remain enabled; cloud system tests are skipped.

Real-workspace acceptance for the episode branch under a custom chain id is still outstanding, as is the batch-mode real-workspace acceptance carried over from v0.12.41.
