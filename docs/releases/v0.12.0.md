# Release Notes - v0.12.0

Two features headline this release: **config override overlays** — declare
per-pipe and per-entity configuration in YAML with glob patterns and have it
land on registered metadata before anything executes — and an **artifact
store abstraction** that makes Unity Catalog volumes (and local directories)
first-class artifacts locations for the CLI, alongside the existing Azure
storage accounts.

## Config override overlay (`datapipes:` / `dataentities:`)

Top-level config sections now overlay registered pipe and entity metadata,
keyed by glob patterns over dot-segmented ids:

```yaml
datapipes:
  "bronze.*":
    tags:
      layer: "bronze"
      sla: "4h"
  "bronze.ingest_orders":
    use_watermark: true

dataentities:
  "silver.*":
    tags:
      team: "core"
  "silver.customers":
    merge_columns: ["customer_id", "region"]
```

Patterns resolve least→most specific (exact id beats `*`, which beats
`**`; mappings deep-merge, scalars and lists replace). Bootstrap applies
the overlay once after local package registrations import, and the
compiled patterns persist — pipes and entities registered later (workspace
packages, app `register_all()`, notebook cells) are overlaid at
registration, so overrides are always in effect before execution.

Resolution always starts from the original declaration parameters, making
the pass idempotent and hot-reloadable (`config_service.reload()` +
`bootstrap.apply_config_overrides()`). Identity and structural fields
(`pipeid`/`execute`, `entityid`/`schema`/`sql`) are never overridable.
Entity validation re-runs on overlaid metadata and fails fast at bootstrap
with config-overlay context; SCD2 current-row companions converge with the
config (enabling SCD by config creates the companion, disabling removes
it). Runtime channels keep their per-read precedence above baked patterns:
`set_entity_tags`, then `tag_overrides`. Underscore keys (`_enabled`,
`_remove_tags`) are carried but not yet interpreted — that lands with tag
management (gh#32).

## Artifacts on Unity Catalog volumes (and local paths)

The CLI no longer assumes the artifacts location is an Azure storage
account. The path's shape now selects the backend — the same
`artifacts_storage_path` string the runtime already interprets on-cluster:

```bash
# One variable configures both the CLI and the runtime:
export KINDLING_ARTIFACTS_STORAGE_PATH=/Volumes/main/kindling/artifacts

kindling workspace init --platform databricks
kindling package deploy my-domain-package
kindling runtime deploy --source github:latest --dest /Volumes/main/kindling/artifacts
```

- `abfss://…` → Azure Blob/ADLS (existing behavior, byte-for-byte,
  including sovereign-cloud endpoints and the legacy
  `AZURE_STORAGE_ACCOUNT`/`AZURE_CONTAINER`/`AZURE_BASE_PATH` variables).
- `/Volumes/<catalog>/<schema>/<volume>/…` → Databricks Files API. Auth
  follows the standard chain (`DATABRICKS_TOKEN`, the `AZURE_*` service
  principal, or Azure CLI login); access is governed and audited by Unity
  Catalog grants — no storage-plane RBAC needed.
- A local directory or `file://` → filesystem, handy for tests and local
  development (the deploy commands now work end-to-end against a tmp dir
  with no cloud credentials at all).
- `dbfs:/` roots are rejected with a pointer to volumes (DBFS root storage
  is deprecated by Databricks).

`runtime deploy --source/--dest` accept any store root, so staging→prod
promotion works across backends. Store paths are validated against root
escape (`..`, absolute paths) on every operation. Requires
databricks-sdk ≥ 0.20.0 for volume roots.

## Also in this release

- **`kindling.reset()`** — public API to clear in-process framework state
  (DI container, config service, registries, signal handlers) for notebook
  recovery and test isolation. Spark sessions and external resources are
  deliberately untouched.
- **Per-run entity tag overrides** — `run_datapipes(..., entity_tags={...})`
  applies JIT tag overrides for that run only, then restores; the parameter
  channel for values like a provider read window in a backfill loop.
- **Extension namespace unification** — the remaining `kindling-ext-*`
  distributions are republished as `spark-kindling-ext-*`; both naming
  generations keep working in `kindling.extensions` config.

## Fixes

- Extension import resolution no longer guesses module names from pip
  names — import-time DI registration now runs reliably for renamed
  distributions, and the already-installed check stops re-downloading
  wheels every bootstrap.
- Databricks startup no longer eagerly scans the entire workspace to prime
  the notebook cache (minutes of `initialize()` latency on large
  workspaces); the scan is lazy, timeboxed, and logged.
- `adx-api` reads with Kusto `dynamic` columns no longer fail during Arrow
  conversion; dict/list values serialize to JSON strings.

## Upgrade notes

Domain devcontainers: `kindling env update` (available since 0.11.x)
refreshes an existing container to this release without a rebuild. The
published devcontainer image for 0.12.0 includes it; if your container
predates it, `docker pull` the new image and rebuild once. Note that
Docker never re-pulls a cached `:latest` tag on its own — pull explicitly
(or pin the image tag) when picking up a new release.
