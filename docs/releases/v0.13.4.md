# v0.13.4 — Extensions on Databricks Runtime 17.x, Temporal on Spark 4

A patch release for problems found by running the extension system tests on Databricks Runtime 17.3 LTS (Spark 4.0, Python 3.12). The CI cluster runs that version, and so may production Databricks.

Package versions:

- Runtime, CLI, SDK: **0.13.4**.
- Temporal extension: **0.2.8**.
- Other extensions: unchanged (Databricks 0.2.0, Databricks Auto Loader 0.1.0, SDP 0.3.4, Cosmos DB 0.2.0, ADX 0.1.0, OpenTelemetry Azure 0.4.0, Visualization 0.1.0).

## Extensions load on Databricks after upgrading a package the runtime already uses

Databricks imports some packages itself, such as OpenTelemetry, before Kindling starts. When an extension's install upgraded one of them, the bootstrap left parts of the old copy loaded. The new code then failed against them. For example, the OpenTelemetry Azure extension never loaded (`cannot import name '_ExtendedAttributes'`).

After each install, the bootstrap now unloads every module of each package the install changed. That covers submodules, compiled modules and modules the upgrade removed, so the next import gets the new copy. Packages the install didn't change stay loaded, so no package ends up loaded twice. A failure importing an extension is now a warning instead of stopping the bootstrap.

## Temporal: invalid condition SQL is quarantined on Spark 4

On Spark 4 (Databricks Runtime 17.x, classic and Spark Connect), the Temporal extension's condition validator let every condition through. A condition with invalid SQL was saved and then failed the pipe run, instead of being quarantined.

Temporal 0.2.8 checks condition SQL in a way that works on Spark 3 and 4:
- **Syntax error:** the condition is quarantined.
- **Unknown column or function:** still accepted, since conditions are checked before they meet real events.
- **Spark can't run the check at all** (no session, a connection failure): ingestion fails with `ExpressionValidationUnavailable` so it can be retried. A rule is never rejected without being checked.

## Other changes

- **New Databricks job clusters default to DBR 17.3 LTS** instead of 13.3, which Databricks no longer supports. Jobs that set a Spark version are unaffected.
- **Dynaconf `>=3.1.0,!=3.3.4,<3.3.6`**, locked at 3.3.5, the version clusters install. Only 3.3.4 has the `@format` merge bug Kindling guards against, and it was fixed upstream in 3.3.5.

See `CHANGELOG.md` for details.
