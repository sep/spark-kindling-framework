# v0.14.2 — Fabric Runtime 2.0, run records, input versions

A feature release on the 0.14 line. Kindling now runs on Fabric Runtime 2.0
(Spark 4.1) in place of Runtime 1.3, provenance stamps record the version of
each input a pipe read, and each initialization can be recorded in a
`system.runs` table. New features are off by default.

Before 1.0, Kindling shifts semver one place right: a `0.MINOR` release may
break things and a `0.x.PATCH` release brings features and fixes. No one is
known to run Kindling on Fabric Runtime 1.3 in production, so dropping it
ships here rather than in a 0.15.0.

Package versions:

- Runtime, CLI, SDK: **0.14.2**.
- SDP and Databricks extensions: **0.14.2** (both require
  `spark-kindling>=0.14.1,<0.15`; Databricks also requires SDP 0.14.1 or
  later).
- Temporal extension: **0.14.1** (requires `spark-kindling>=0.14.0,<0.15`).
- Other extensions: unchanged at **0.14.0** (Cosmos DB, OpenTelemetry Azure,
  ADX, Databricks Auto Loader, Visualization). They work with 0.14.2.

## Fabric Runtime 2.0

Kindling is system-tested on Fabric Runtime 2.0 (Spark 4.1, Python 3.13) and
no longer supports Runtime 1.3.

- The `fabric` extra no longer caps `azure-core` below 1.31, and neither does
  `spark-kindling-sdk`. Runtime 2.0 ships azure-core 1.39.0, which the cap
  would have tried to downgrade. The extra is kept, empty, so
  `spark-kindling[fabric]` installs keep working.
- The OpenTelemetry Azure extension installs on Runtime 2.0. The runtime
  ships OpenTelemetry 1.16, older than the extension supports, so the
  bootstrap now leaves OpenTelemetry unpinned there instead of failing the
  pinned install and retrying.
- The `standalone` and `all` extras allow `pyspark` and `delta-spark` up to
  `<5.0.0`, so a local install can use Spark 3.4-3.5 or 4.x. Their `pandas`
  and `pyarrow` floors rise to `>=2.2.0` and `>=15.0.0`.

## Tested runtimes and the untested-runtime warning

The runtimes Kindling is system-tested on (Databricks Runtime 17.3 LTS,
Fabric Runtime 2.0, Azure Synapse Spark 3.5) and the key packages each ships
now live in the wheel as `kindling.supported_runtimes`. At startup the
runtime manifest records how the running runtime compares in
`runtime_match` (`tested`, `partial`, `untested` or `unchecked`).

Bootstrap warns on an untested runtime (another DBR version, serverless,
another platform) and when a key package or Python differs from the closest
tested runtime at major.minor, naming the packages. Standalone is never
warned about.

## `system.runs`

Turn it on with:

```yaml
kindling:
  runs:
    enabled: true
```

Each initialization then gets a row in the `system.runs` Delta table, stored
like `system.watermarks`. The row is inserted as `running` when
initialization completes and updated to `succeeded` or `failed` (end time,
error, executor run ids) when an auto-run app ends. It holds the app,
platform, runtime and version fields, `runtime_match`, both fingerprints and
the full runtime manifest as JSON, and joins to provenance stamps on
`run_id`. A failed write is only a warning.

Watermarks now save the executor's run id (the provenance stamps'
`execution_id`) as `last_execution_id`, so a watermark links to the run that
advanced it.

## Provenance `input_versions`

A stamped batch write records the version of each input its pipe read in the
stamp's `input_versions` map:

- A watermarked input records the cursor its read covers.
- A Delta input is read pinned at the table version it records, so the stamp
  names exactly the snapshot the pipe read, even when a commit lands before
  the write. If the version lookup fails, the input is read normally and left
  out of the map.
- Inputs of other providers are left out. Streaming and SDP stamps keep the
  map null.

Reads only pin when the pipe's output is stamped. Providers can offer
versioned reads with the new `VersionedReadableEntityProvider` interface.

## Upgrading from 0.14.1

1. **Move Fabric environments to Runtime 2.0.** Runtime 1.3 is no longer
   supported or tested.
2. **Upgrade the Databricks extension with the Temporal extension.** The
   Databricks extension 0.14.1 and earlier can't declare a temporal chain on
   Lakeflow with Temporal 0.14.1. Move both, e.g. with `kindling env update`.
3. **`kindling.lakeflow.allowed_apps` is no longer read.** It sat in the same
   pipeline-configuration block as `kindling.data_app`, so it never
   authorized anything. A pipeline that still sets it is unaffected; remove
   it from bundle and Terraform configuration when convenient.
   `LakeflowAppNotAuthorizedError` is gone.
4. **Config-key and tag-name constants are no longer exported** from the
   Databricks, SDP and Temporal extension package roots. Spell the key as a
   string literal if you imported one. See `CHANGELOG.md` for the list.

## Fixes

- **Databricks apps no longer stall about 80 seconds per missing optional
  file.** A missing `abfss://` file fell back to the ADLS SDK, whose
  credential chain waited out its managed identity retries on clusters with
  no Azure credential: about 5.5 minutes per run for a typical app.
- **`kindling migrate` no longer plans removing framework-owned columns**
  (SCD2 temporal columns, surrogate keys, the provenance column).
  `migrate apply --destructive` would have dropped them.
- **Fabric jobs no longer drop settings whose values contain spaces**, and
  `spark_configs` passed in a Fabric job's `config_overrides` now reach Spark.
- **The SDK's log streaming waits for an app's last output on Fabric** and no
  longer waits 10 minutes after a Synapse job ends.

## For contributors

- System tests are faster: Synapse from about 28 to about 20 minutes, two
  avoidable waits removed, and the Databricks cluster warmed up before the
  tests start.

See `CHANGELOG.md` for details.
