# v0.12.43 — Registry-declared conditions in Lakeflow temporal chains

The Databricks Lakeflow stratified temporal lowering resolved condition rules from the conditions table only. An app declaring its rules through `DataConditions.register` therefore lowered a pipeline that never emitted those rules' boundary events, so an episode opened by a base event and closed by a registry-backed condition had no end boundary at all and ran to its synthetic expiry.

Package versions:

- Runtime, CLI, SDK: **0.12.43**.
- Databricks extension: **0.1.13**, requiring runtime **0.12.39+** and SDP **0.3.2+**.
- Temporal extension: **0.2.7**.
- SDP extension: **0.3.3** (unchanged since 0.12.40).

The failure was silent in both directions. The conditions read swallowed *every* exception into an empty rule set, so a permissions error or an unreadable table looked exactly like a first run; and an absent condition is indistinguishable from one not yet ingested, which is a legitimate state the lowering must tolerate. Nothing logged, nothing raised, and the affected episodes were materially indistinguishable from correctly-expired ones except by their end boundary: `end_event_synthetic = true`, no resolvable end event type, and `end_time = start_time + expires_after`.

`declare_temporal_chain` has always merged both sources; only the Lakeflow lowering diverged. It now resolves both, gated by each declared engine's `condition_source` exactly as the chain gates them — a registry-only chain reads no conditions table at all, and a table-sourced chain is unchanged.

Generation layering is computed over the **combined** rule set rather than per source. This is not a detail of the merge: the Lakeflow topology fixes its stratum count at declaration time, so a rule layered against a partial graph takes the default generation 1 and lands in the wrong stratum. The chain executor never had this exposure because it runs an iterative fixpoint loop instead of a static graph.

To stop the two lowerings drifting again, the cross-source checks (`condition_id` collisions, cross-source cycles) and the layering moved into shared helpers in the temporal extension — `combine_condition_rules` and `layer_rules_by_generation` — called by both. That merge point also now drops disabled rules: `validate()` already excluded them from a table-sourced set, but `get_all_conditions()` returns every registration and `execute_rules` runs whatever it is handed, so a registry rule declared `enabled=False` previously emitted boundary events and occupied a generation on **both** paths.

The silence is fixed alongside the omission. A conditions read re-raises anything that is not catalog-level absence — a registered table whose storage path is missing or unreadable is corruption, not a first run — and the resolved rule counts per source and per stratum are logged at declaration.

Upgrading: deploy the **0.1.13** Databricks extension wheel, then re-emit the missing boundary events over history. Which step that is depends on `kindling.lakeflow.temporal_mode`:

- `batch` — the strata are recomputed per update, so a normal triggered update self-corrects.
- `streaming` (the default) — `<events>__g1..gK` are streaming tables whose sources are already checkpointed, so the newly-included rules fire only for newly-arriving rows. A full refresh of the boundary strata is required. `<events>__g0` already holds every base event, so refreshing only the numbered boundary strata avoids re-reading bronze.

Episodes are written by AUTO CDC from-snapshot with `stored_as_scd_type=2`, so corrections chain SCD2 versions rather than overwrite: downstream consumers must filter to current rows or they will see both the expired and the corrected closed version of the same `episode_id`. Both the `.expired` and the corrective `.closed` determination events will exist in the events surface, by design — their deterministic event ids differ.

Validation: 2,963 unit tests passed (2 skipped); black, isort and flake8 clean, with no new pylint message categories on the touched files. The regression test invokes the emitted boundary stratum's query body and asserts the registry rule is what it runs, verified to fail against the unfixed lowering; ten further tests cover registry-only chains never touching the conditions table, the table path unchanged, combined-graph layering, disabled-rule filtering, both read-error branches, and the collision check. This is a fast-track release: release wheel builds and smoke tests remain enabled; cloud system tests are skipped.

Real-workspace acceptance of the corrected episode branch is outstanding, as is the batch-mode real-workspace acceptance carried over from v0.12.41.
